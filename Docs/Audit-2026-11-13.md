## 本轮已修正的问题

1. **Surge 历史数据回退**：Spotify 移除无标签边界的 `spotify` 关键词及两条旧 Google Cloud IPv4；两个 Akamai 主机改回精确域名，和其他五端一致。Apple、Telegram、WeChat 移除合计 10 条重复匹配对象的 no-resolve 变体；Parsec 两份文件补齐真实条数。没有删除这些重复项覆盖的 IP/ASN 匹配对象。
2. **Netflix 共享服务误归类**：六端均移除 `us-west-2.amazonaws.com`、`cookielaw.org`、`onetrust.com` 的整域后缀。旧规则会将 DynamoDB、区域 S3 及其他网站的同意管理请求归入 Netflix。保留现有专用 Netflix、nflx、已收录 CDN 主机与 IP 数据，没有换成整个云厂商网段。
3. **Telegram 共享分析端点**：六端移除 `api.mixpanel.com`，这是 Mixpanel 的通用接收 API，不能仅凭目的主机认定为 Telegram。
4. **品牌关键词误匹配**：Google 每端移除 6 条、Meta 4 条、Microsoft 4 条无标签边界的通用品牌关键词。既有精确主机和专用后缀继续保留；`google.example.org`、`instagram.example.org`、`onedrive.example.org` 等离线反例不再命中。
5. **WeChat 的 IP 片段域名关键词**：六端每端移除 233 条，例如 `101.226.129.`。它们不是 IP-CIDR，会误匹配含该片段的普通域名；没有据此猜测或新增 /24 网段。保留明确域名、现有 CIDR、ASN 和可见 HTTP User-Agent 条件。
6. **Clash 扩展脚本优先级**：SiriAI 排在 AI 前；服务专用集合排在 Google、Apple、Microsoft 通用集合前，避免例如 GitHub Actions 的 `productionresultssa0.blob.core.windows.net` 先被 Microsoft 捕获。LAN、ParsecP2P、NTP 的前置与 Parsec 控制连接代理继续保留。
7. **Clash 用户设置被覆盖**：已有同名提供者的 URL、缓存路径、下载策略与更新周期保持原值；已有匹配策略和选项保持原字符串；自订 `Horatio-*` 规则与重复的用户策略变体不会被前缀过滤删除。扩展脚本重复执行不增加规则。订阅的节点、策略组、DNS、TUN 与末尾兜底保留。
8. **文档与持续校验**：修复接手文档中 70 个失效或大小写错误的公共路径，更新 Surge 真实条数，保留其余本地文字。新增维护校验工具、服务反例与只读 CI；这些工具不参与客户端日常运行。
