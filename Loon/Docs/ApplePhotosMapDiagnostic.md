# Apple 照片地图诊断 0.1.0

目标是让中国大陆拍摄的照片使用对应的国内地图数据，境外照片使用对应的国际地图数据，切换依据应当是地图所展示的地点。当前交付的是排查所需的诊断插件，**自动分源与定位修复尚未实现**。不要把日志中的命中当成照片位置已经修复。

## 安装和提供诊断

要求 Loon **3.5.1 (983)** 或更新版本。将下方地址添加到 Loon 的远程插件中并启用；确认 Loon 的 HTTPS 解密和已经安装、信任的 MitM 证书可用。

```text
https://raw.githubusercontent.com/hhhoratioxu/Proxy/codex/apple-photos-map-diagnostics/Loon/script/ApplePhotosMapDiagnostic.plugin
```

1. 打开“照片”，找一张位置原本正确的中国大陆照片，上滑打开地点小地图，再点开地图并放大。
2. 在 Loon 的脚本日志中复制这一时段以 `[ApplePhotosMapDiagnostic]` 开头的内容。
3. 对一张偏移的境外照片重复同样操作，分别标明“国内照片”和“境外照片”；附上 iOS 版本、实际拍摄国家或地区、偏移大约几百米还是另一个城市。
4. 诊断完成后停用本插件。

**只需分享本插件输出的摘要行**，无需发送照片、完整网络记录、抓包文件或整条请求 URL。Loon 的其他网络日志可能包含坐标和令牌，本插件不控制那些日志。若插件没有输出，先查看所打开页面是否使用了缓存，以及对应 HTTPS 请求是否完成解密；不要反复修改照片的位置，也不需要清空照片图库或改动系统定位。

如果其他地图脚本已启用，Loon 每次请求/响应只执行第一条完整命中的 Script，诊断可能没有机会运行。可先记录当前状态，在这次短时排查时停用冲突的地图脚本，结束后恢复。当前插件暂未在真实 Loon/iPhone 中导入验收。

## 能观察什么

脚本仅匹配配置中明确列出的 Apple 地图资源清单、单个地图瓦片与两种地点调度接口。请求阶段只读取 URL 中已知参数的**名称**；允许显示缩放级别及地图样式、比例、尺寸等有限整数。响应阶段仅解析不超过 1 MiB 的资源清单，输出瓦片总数、国内/国际服务器数量和位置转换服务类别；地点调度响应只观察状态和内容类型，不读取正文。

未知参数只计数，URL、经纬度、瓦片 x/y、照片标识、账户、令牌、Cookie、请求头和原始正文均不输出。所有路径通过 `$done({})` 保留原请求/响应。没有脚本网络请求、持久缓存、定时任务或外部收集服务器；实际地图流量仍由原请求发送给原服务商。

这些接口可能由其他使用 MapKit 的应用共用，Loon 的这些规则无法验证调用者一定是“照片”。请分别打开两张照片，靠操作时间区分日志。未知协议、超过范围的域名与路径不捕获；批量瓦片、HTTP/3/未能解密的流量、系统本地转换以及缓存地图可能不可见。

## 当前证据与未完成部分

2026-10-19 已在桌面直接取得 Apple 返回的国内版与国际版资源清单。测试请求中的 `country_code=US` 与 `country_code=CN` 对 iOS 返回的数据源相同，JP 请求返回的瓦片端点不同。因此，只改地区参数无法证明拿到了正确的底图，也无法证明照片坐标转换正确。此观察限于当时使用的测试参数与网络，并非所有 iPhone 的结论。

尝试构造单瓦片请求时得到 HTTP 403/500，尚未取得可用于验证照片渲染的真实客户端瓦片请求。本插件不据此猜测鉴权参数、不强行混用不同版本的瓦片和底图样式。还需要目标 iPhone 的摘要及症状，判断下一步应处理底图选择、地点解析还是本地显示转换。如果问题发生在系统本地转换或已写错的照片元数据，仅修改网络请求未必能解决。

34 项本地检查全部通过：包含四份真实 Apple 资源清单、敏感值不进入日志、畸形与超限输入退回、250 份随机输入和 1,000 次连续调用。检查对象包括实际安装文件的 URL 范围、正文读取范围与 MitM 域名。未运行 Loon 原生配置解析器，也未在 iPhone 中导入或验证位置。这些检查仅验证诊断和原样放行，不是自动分源或照片位置修复的验收。
