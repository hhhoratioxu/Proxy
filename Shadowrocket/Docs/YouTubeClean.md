# YouTube Clean 1.2.1 · Shadowrocket

**1.2.1 修复版**：去广告、双语字幕与发布「＋」/Shorts 独立隐藏开关。用户反馈 1.2.0 B 仍有广告，并提供 Loon 3.5.3(1008) 的 initplayback 完成记录；本版修复压缩响应与明文播放元数据处理，并补齐明确诊断。实际漏广告的原因尚需新日志确认。

## 安装和使用

添加远程模块，修改时同步更新两条 Script 的 argument。该客户端使用兼容接口适配，尚未获得完整官方规范，未标为官方验证。

停用旧版本和其他处理相同请求的 YouTube 插件，只启用当前选中的一个方案。确认你自己的 HTTPS 解密证书已安装并信任，客户端已开启解密。保存后强制退出 YouTube，再重新打开并下拉刷新主页。

| 设置 | 默认 | 用途 |
| --- | --- | --- |
| `REMOVE_ADS` | `true` | 广告处理 |
| `TRANSLATE_CAPTIONS` | `true` | 已有字幕翻译 |
| `TARGET_LANGUAGE` | `zh-Hans` | 简体中文，可选繁体等 |
| `BILINGUAL` | `true` | 原文在上、译文在下 |
| `AUTO_CAPTIONS` | `true` | 优先新增字幕轨道 |
| `HIDE_UPLOAD` | `true` | 隐藏底部发布「＋」 |
| `HIDE_SHORTS` | `false` | 隐藏底部 Shorts，普通 Shorts 视频保留 |
| `DEEP_FILTER` | A 为 `false`，B/C 为 `true` | 深查广告封装和徽标，也会隐藏推广/试用卡片 |
| `DIAGNOSTICS` | `true` | 输出结构诊断日志，可关闭 |

Loon 的三版分别针对元素识别、深层卡片识别和连接兼容性。当前主页仍有广告时先试 B。**A/B/C 每次只启用一个**，否则第一条命中的脚本可能使其他方案无法执行。三版保留双语字幕和底栏开关。

C 版仅拒绝 `youtubei.googleapis.com`、`youtubei-att.googleapis.com`、`www.youtube.com`、`m.youtube.com` 的 UDP/443，用于测试回退到可解密的 TCP；不拦截其他域名或 `googlevideo.com` 媒体主机的 UDP。客户端是否回退及已有本地规则的优先级需要实际检查，可能有加载延迟。其他客户端没有额外发布 C 版路由规则，可在当前入口设置 `DEEP_FILTER=true` 使用深层过滤。

## 仍显示广告时

确认名称显示 **1.2.1** 和所选方案，并开启「去广告」「输出结构诊断日志」。更新后强制退出 YouTube，再打开主页下拉刷新。日志以 `[YouTubeClean]` 开头，记录固定接口名称 `endpoint`、处理原因 `reason`、是否改动 `changed`、数据大小、密钥可用状态及有限的结构标识；不输出账号、视频标题、Cookie、Authorization、完整 URL、访客标识、字幕签名或密钥内容。没有通知弹窗、定时任务或外部上报。

对于主页广告，优先提供 `endpoint` 为 `browse` 的诊断行；`initplayback` 是播放封装接口，记录完成本身无法证明主页卡片已被清理。1.2.0 没有播放接口诊断，1.2.1 已补齐。

| `reason` | 含义 |
| --- | --- |
| `modified` | 这次响应已被修改，查看 `removedParts` 和接口名称 |
| `unchanged` | 解析后没有产生改动，结构标识可帮助识别漏掉的广告 |
| `key-missing` / `key-expired` / `key-invalid` | 加密播放元数据缺少有效密钥，保持原数据 |
| `stream-auth-failed` | 播放元数据验签失败，保持原数据并使当前会话密钥失效 |
| `decode-failed` | 不支持或损坏的数据格式，保持原数据 |
| `no-target-metadata` | 播放封装内没有当前支持的目标元数据 |
| `http-status` / `empty-body` / `body-too-large` | 状态码、正文或大小限制使处理跳过 |

只需复制上述诊断行，无需提供带查询参数的完整 Match URL、账号信息或完整抓包。没有 `browse` 记录时尚不能确认主页请求命中；C 版可测试 API 连接兼容性。有 `browse` 但未修改时，需要根据模板/字段标识继续补齐识别。

## 1.2.1 处理修复

- 原始 gzip 响应在限制内解压并校验后处理；已经解压的正文按真实字节识别。未修改或校验失败时保留原响应。
- 没有 CryptoParams 的明文 Onesie 播放器封装，在确认状态和正文后可直接处理，不再要求先取得密钥；加密内容仍需要有效密钥并验签。
- 没有有效密钥时，启动阶段的 browse/guide 也请求刷新热配置；有效密钥存在时保留热配置哈希。帧格式错误不会误清除有效密钥。
- 支持的请求/响应均有明确处理结果；诊断可以在设置里关闭。

这些分支已通过独立构造数据复现与测试，不能从先前一条完成记录认定它们就是用户广告残留的原因。

## 处理范围

广告元素按已确认的 protobuf 结构读取静态模板名称；深层模式只检查单张推荐卡片，不扫描整个账号数据或全局模板资源。模板命名识别是启发式策略，仍可能漏掉不同的服务端广告实验。B/C 也会隐藏推广和试用卡片。创作者口播推广不在自动处理范围内。

翻译依赖视频已有字幕及 YouTube 翻译，原文在上、译文在下，原轨道保留。没有字幕时不能生成语音识别字幕。原字幕请求最多一次、限时 4 秒，不转发账号凭证、不跟随重定向，无需购买翻译 API。

二进制处理上限 8 MiB，字幕 1 MiB。未知或错误数据、认证失败及不支持的压缩保持原响应；缺少密钥时保留加密元数据；普通 videoplayback 不运行响应脚本。播放密钥只存于当前代理客户端本地。

2026-10-17：**112 项本地检查通过**，包括五种客户端接口、Loon 三份实际生成配置与默认参数、原生元素广告、深层封装/徽标、推广过滤、相邻普通卡片保留、C 版规则范围及日志隐私，新增 gzip、明文 UMP、密钥与诊断分支。真实公开初始主页和继续加载响应加入自写广告后，处理可逐字节保留其余数据；原始匿名样本没有投放中的主页广告。
